# บันทึกความคืบหน้าเว็บไซต์ CHNS

## 5 ตุลาคม 2569 — Hero ภาพล้วนและ header มือถือแบบแฮมเบอร์เกอร์

- หน้าแรกไม่วางข้อความทับภาพ hero อีกต่อไป: กรณีไม่มีสไลด์แสดงภาพนิ่งเต็มความกว้าง (`home-hero-still`) และย้ายชื่อองค์กรกับปุ่ม "สำรวจภารกิจ/รู้จักเรา" ไปไว้ในแถบใต้ภาพเหมือนกรณีมีสไลด์; ลบสไตล์ `home-lead` ที่ไม่ใช้แล้ว
- เปลี่ยนปุ่มเมนูมือถือจากข้อความ "เมนู" เป็นไอคอนแฮมเบอร์เกอร์ที่เปลี่ยนเป็นกากบาทเมื่อเปิด และเปลี่ยนเมนูเป็น drawer เลื่อนจากขวาพร้อมฉากหลังทึบ
- Drawer มีหัวเมนู (โลโก้ + ปุ่มปิด) รายการเมนูเลื่อนได้ และส่วนท้ายตรึงปุ่ม "ร่วมสนับสนุน" กับลิงก์ค้นหา; ปิดด้วยปุ่มปิด คลิกฉากหลัง ปุ่ม Esc หรือเมื่อเปลี่ยนหน้า พร้อมล็อกการเลื่อนหน้าและคืนโฟกัสให้ปุ่มเปิดเมนู
- ตรวจบนเบราว์เซอร์จริงที่ 360/390 px และ 1280 px: ไม่มีแนวนอนล้น เมนูย่อยกางได้ เดสก์ท็อปยังใช้เมนูเดิม; `npx tsc --noEmit` และ `npm run lint` ผ่าน

## 26 กันยายน 2569 — แสดงโครงการตัวอย่างบนเว็บ

- ขยายโครงการจำลองเดิม 3 รายการและเพิ่มใหม่ 3 รายการ รวม 6 รายการพร้อมภาพปกและรายละเอียดหลายย่อหน้าใน Supabase
- เปิด `showcase_visible=true` เฉพาะชุดนี้เพื่อแสดงการ์ดบนหน้าแรก หน้ารวมโครงการ หน้ารายละเอียด และผลค้นหา โดยยังคง `draft` + `is_mockup=true` และป้ายเตือนว่าไม่ใช่ภารกิจจริงหรือช่องทางรับเงิน
- เมื่อมีโครงการจริงที่เผยแพร่แล้ว หน้าแรกและหน้ารวมจะเลือกโครงการจริงแทนตัวอย่างโดยอัตโนมัติ
- ตรวจหน้าแรกและหน้ารวมบนเว็บจริงในเครื่อง: การ์ด 6 รายการ ภาพครบ หน้ารายละเอียดตอบ 200 ไม่มีแนวนอนล้น; `npm run lint`, `npm run build` และ `npm run supabase:verify` ผ่าน

## 26 กันยายน 2569 — แสดงข่าวตัวอย่างบนเว็บ

- ผู้ใช้ระบุว่าต้องการเห็นข่าว Mockup บนหน้าเว็บ จึงเปิดเฉพาะ 11 รายการที่เตรียมไว้ด้วย `showcase_visible=true` โดยยังคง `draft` และ `is_mockup=true`
- หน้าแรก หน้าข่าว หน้ารายละเอียด และผลค้นหาแสดงตัวอย่างพร้อมป้ายชัดเจน; ภาพจาก private Storage เปิดเฉพาะไฟล์ของรายการตัวอย่างที่ระบุ ไม่เปิดร่างอื่น
- เมื่อมีข่าวจริงที่เผยแพร่แล้ว รายการข่าวและหน้าแรกจะเลือกข่าวจริงแทนตัวอย่างโดยอัตโนมัติ

## 26 กันยายน 2569 — เติมข่าวและบทความตัวอย่างใน Supabase

- ขยายตัวอย่างเดิม 3 ชิ้นและเพิ่มใหม่ 8 ชิ้น รวม 11 ชิ้น เป็นข่าว 6 และบทความ 5 พร้อมเนื้อหาหลายย่อหน้าและภาพปกสำหรับพรีวิวหลังบ้าน
- ทุกรายการเป็น `draft` และ `is_mockup=true`; ระบุในเนื้อหาว่าเป็นแบบจำลอง ไม่ใช่เหตุการณ์จริง และฐานข้อมูลป้องกันการเผยแพร่ตัวอย่าง
- เพิ่มสคริปต์ `scripts/seed-article-mockups.mjs` เพื่อเติมข้อมูลซ้ำอย่างปลอดภัย และปรับสคริปต์ตรวจ Supabase ให้ตรวจจำนวน เนื้อหา ภาพ และสิทธิ์ร่าง

## 26 กันยายน 2569 — รวมโลโก้องค์กรสมาชิกไว้หน้าแรก

- แสดงโลโก้องค์กรสมาชิกและภาคีที่เผยแพร่แล้วทั้งหมดในส่วน `/#network` เป็นตารางโลโก้พื้นขาวแบบกระชับ ปรับจำนวนคอลัมน์ตามหน้าจอ
- เปลี่ยนลิงก์เมนู Footer หน้าศูนย์ประสานงาน และหน้าสมัครสมาชิกให้ไปส่วนนี้; ผลค้นหาองค์กรเลื่อนไปยังโลโก้รายการนั้นโดยตรง
- ยกเลิกหน้าเนื้อหา `/members` และส่งต่อ URL เดิมไป `/#network` เพื่อรักษาลิงก์ที่เคยใช้งาน
- ตรวจหน้าเดสก์ท็อปและมือถือ: โลโก้ 47 ภาพโหลดครบ, แสดง 12/4 คอลัมน์โดยไม่มีแนวนอนล้น; `npm run lint` และ `npm run build` ผ่าน, `/members` ตอบ 308 ไป `/#network`

## 26 กันยายน 2569 — ออกแบบส่วนร่วมกับเราและ Footer ใหม่

- เปลี่ยนแถบ CTA ท้ายหน้าแรกจากพื้นเขียวทึบและหัวข้อขนาดใหญ่เป็นพื้นเขียวอ่อน พร้อมทางเลือกสองทางที่แยกผู้สนับสนุนกับองค์กรชัดเจน
- จัด Footer เป็นกลุ่มแบรนด์ ช่องทางติดต่อ และเมนูสองคอลัมน์; เพิ่มเวลาทำการและลิงก์แผนที่จากข้อมูลติดต่อที่อนุมัติไว้แล้ว พร้อมแถว Social และลิงก์ข้อมูลส่วนบุคคล/คุกกี้
- ตรวจการจัดวางเดสก์ท็อปและมือถือ; `npm run lint` และ `npm run build` ผ่าน

## 26 กันยายน 2569 — ซ่อนบล็อกรายงานที่ยังไม่มีข้อมูลบนหน้าแรก

- เอกสาร Revision Brief 01 ระบุ “รายงาน” ในลำดับหน้าแรกและ user flow แต่ไม่ได้บังคับชื่อ ACCOUNTABILITY หรือข้อความอธิบายที่เว็บไซต์เคยแสดง
- หน้าแรกจะแสดงส่วนรายงานเมื่อมีรายงานที่เผยแพร่จริงอย่างน้อยหนึ่งรายการ; ระหว่างนี้ไม่มีข้อความ placeholder และยังเข้าหน้ารายงานได้จากเมนู/ท้ายเว็บ
- ตรวจหน้าแรกหลังแก้; `npm run lint` และ `npm run build` ผ่าน

## 26 กันยายน 2569 — ลดรายการซ้ำบนหน้าแรก

- เอาแถบทางลัด 01–03 ที่ลิงก์ไปโครงการ ฝ่ายงาน และข่าวสารออก
- เอารายการขั้นตอน 01–03 ในส่วน “จากการประสานงาน สู่การลงมือร่วมกัน” ออก โดยคงข้อความแนะนำและภาพของส่วนนั้นไว้
- ลบข้อมูลและ CSS ที่ใช้เฉพาะสองชุดนี้; ตรวจหน้าแรกและ `npm run lint`/`npm run build` ผ่าน

## 26 กันยายน 2569 — ปรับจังหวะช่องว่างและตัวอักษรทั้งเว็บ

- ตรวจหน้าภายใน 9 เส้นทางด้วยขนาดหน้าจอ 1280 px และตรวจหน้าโครงการ/ประวัติบนมือถือ 390 px; พบหัวหน้าที่มีภาพสูง 808 px บนมือถือเพราะกฎ CSS เพิ่ม padding ซ้ำ
- ลดหัวหน้าภายในแบบมีภาพและไม่มีภาพ ขนาดหัวข้อ และระยะห่างส่วนเนื้อหาให้กระชับขึ้น; ปรับระยะบรรทัดข้อความยาวและช่องว่างในหน้าเกี่ยวกับ/ติดต่อ/ร่วมสนับสนุน
- หลังแก้ หัวหน้าโครงการสูง 433 px บนมือถือ (เดิม 808 px) และ 321 px บนเดสก์ท็อป (เดิม 449 px); หน้าประวัติสูง 221 px บนมือถือและ 183 px บนเดสก์ท็อป; หน้ารายงานบนแท็บเล็ตกว้าง 768 px สูง 411 px
- ตรวจภาพหน้าแรก หน้าโครงการ และหน้าประวัติหลังแก้; `npm run lint` และ `npm run build` ผ่าน

## 26 กันยายน 2569 — เติมเนื้อหาตาม Revision Brief 01

- ผู้ใช้ยืนยันให้เผยแพร่ข้อความในเอกสาร Revision Brief 01; ใช้ปีในประวัติภาษาไทยเมื่อข้อความอังกฤษระบุไม่ตรงกัน และคงภาษาไทยเป็นหลัก
- เพิ่มประวัติ วิสัยทัศน์ พันธกิจ วัตถุประสงค์ ยุทธศาสตร์ บทบาทฝ่ายงาน ศูนย์ระดับภูมิภาค 11 รายการ และช่องทางติดต่อจากข้อมูลที่อนุมัติไว้ใน `src/content/static/organization.ts`; รายการศูนย์ที่เอกสารระบุเป็นตัวอย่างมีป้ายกำกับชัดเจน
- เพิ่ม breadcrumb, ปุ่มแชร์ข่าว/โครงการ, ตัวกรองโครงการ/ข่าว/รายงาน, ค้นหาองค์กรสมาชิกและศูนย์, รวมภาพจากข่าว/โครงการ published ในหน้าสื่อ และแสดงเนื้อหาจากหมวดหรือฝ่ายเดียวกันในหน้ารายละเอียด
- หน้าแรกและหน้าร่วมสนับสนุนแสดงโครงการ ข่าว และรายงานเฉพาะที่ published; เมื่อยังไม่มีข้อมูลจริงแสดงสถานะว่าง โดยไม่สร้างตัวเลขผลลัพธ์หรือวิธีรับเงินขึ้นมาเอง; หน้าสมัครสมาชิกมีช่องทางอีเมลสำหรับสอบถามระหว่างรอระบบรับสมัคร
- เพิ่มข้อมูลติดต่อและ social ใน Footer; ตรวจหน้าแรก/ประวัติบนเดสก์ท็อปและหน้าศูนย์/รายงานบนมือถือ; `npm run lint` และ `npm run build` ผ่าน
- งานที่ยังต้องใช้ข้อมูลเฉพาะเพิ่มเติม: ผังและรายชื่อผู้บริหาร, ศูนย์ระดับจังหวัด, บทบาทฝ่ายกิจการพิเศษ, เนื้อหาและภาพจริงที่เผยแพร่, หลักเกณฑ์คำนวณซะกาต, เอกสารนโยบายข้อมูลส่วนบุคคลและขั้นตอนรับสมัคร, URL เดิมสำหรับ redirect

## 26 กันยายน 2569 — Header แถวเดียวพร้อม CHNS wordmark

- รวมโลโก้ เมนูหลัก และปุ่มร่วมสนับสนุนไว้ในแถวเดียวบนเดสก์ท็อป; เพิ่มคำว่า CHNS ข้างตราสัญลักษณ์ตามภาพอ้างอิงที่ผู้ใช้ส่งมา โดยใช้สีเขียวของเว็บไซต์
- คงการเปิดเมนูย่อยเมื่อชี้บนเดสก์ท็อป และคงเมนูแบบแตะกับปุ่มร่วมสนับสนุนบนมือถือ

## 26 กันยายน 2569 — ปรับทิศทางให้เป็นเว็บไซต์องค์กรทางการ

- วิเคราะห์หน้า UNHCR Thailand ใหม่ตามคำขอ แล้วปรับ Header เป็นพื้นขาวสำหรับโลโก้กับปุ่ม CTA และแถบนำทางสีเขียวที่เปิดเมนูย่อยเมื่อชี้
- เปลี่ยน Hero หน้าแรกเป็นภาพบรรยากาศงานช่วยเหลือเต็มความกว้าง ใช้ภาพจำลองที่มีคำกำกับไว้ชัดเจน และเปลี่ยนภาพวิธีทำงานให้เห็นคนมากขึ้น
- ใช้ขาว เขียวอ่อน และเขียวจากโลโก้ในหน้าแรกกับหัวหน้าหน้าภายใน ลดพื้นที่สีเข้ม สีทอง และลวดลายตกแต่งที่ทำให้เว็บดูไม่เป็นทางการ
- ข้อมูลโครงการ ข่าว และรายงานสาธารณะยังอ่านเฉพาะรายการที่เผยแพร่แล้ว ภาพภารกิจจริงยังต้องได้รับการอนุมัติจาก CHNS

## 26 กันยายน 2569 — เริ่มปรับงานออกแบบทั้งเว็บ

- ออกแบบหน้าแรกใหม่เป็น Hero สองส่วนพร้อมภาพประกอบที่ระบุชัดว่าไม่ใช่ภาพภารกิจจริง ตามด้วยทางลัดไปโครงการ/ฝ่ายงาน/ข่าว ขั้นตอนการประสานงาน รายชื่อฝ่ายแบบ editorial รายงาน ภาคีจำนวนย่อม และช่องทางมีส่วนร่วม
- โครงการ ข่าว และรายงานยังอ่านเฉพาะรายการ published จาก Supabase; ส่วนที่ไม่มีข้อมูลจริงยังไม่สร้างตัวเลข ผลลัพธ์ หรือเรื่องเล่าสมมติ
- ปรับ Hero ที่ใช้ร่วมกันบนหน้าภายในและการ์ดข่าว/โครงการให้เป็นแบบบรรณาธิการ เพิ่มภาพประกอบที่มีคำกำกับในหน้าโครงการ ข่าว และรายงาน; หน้ารวมโครงการมีทางไปดูฝ่ายงานเมื่อยังไม่มีโครงการเผยแพร่
- ตรวจหน้าแรกและหน้ารวมโครงการบนเดสก์ท็อป; `npm run lint`, `npx tsc --noEmit` และ `npm run build` ผ่าน ทิศทางและงานที่ยังเหลืออยู่ใน [redesign-brief.md](redesign-brief.md)

## 26 กันยายน 2569 — เปิดเมนูย่อยด้วยการชี้เมาส์

- ยังไม่เชื่อมโปรเจกต์จริงและยังไม่เปลี่ยน runtime: Better Auth/SQLite เดิมยังทำงานระหว่างรอ URL/key และการย้ายข้อมูล/Auth/ไฟล์บน staging
- เพิ่มหน้า 404 สำหรับ URL ที่ไม่มีและเนื้อหาที่ปิดเผยแพร่, หน้า 403 สำหรับบัญชีที่ไม่มีสิทธิ์ admin, หน้า 500 พร้อมปุ่มลองอีกครั้ง, root layout fallback และ loading state เฉพาะหน้าค้นหา/เนื้อหาเด่น
- ตรวจ HTTP ของ URL ที่ไม่มีและบทความที่ไม่พบเป็น `404`; ผู้ไม่ล็อกอินเข้า `/admin` ถูกส่งไปหน้า login; ตรวจภาพหน้า 404 บนจอกว้าง และ `npm run lint`/`npm run build` ผ่าน
- SQL migration ยังไม่ผ่านการรันจริง เพราะยังไม่มี Supabase project/staging; ต้องทดสอบ RLS/Storage กับบริการจริงก่อนสลับระบบ
