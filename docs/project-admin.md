# โครงการ: โมดูลหลังบ้านเฟส 2

สถานะ: ใช้งานในเครื่องได้สำหรับผู้ดูแล `admin`; ยังไม่ใช่ workflow โครงการเต็มรูปแบบที่มีตัวเลขผลลัพธ์ หลักฐาน และการอนุมัติหลายระดับ

## การใช้งาน

1. เข้าสู่ระบบที่ `/admin/login` แล้วเปิด `/admin/projects`
2. ระบุ URL slug, ชื่อ, ประเภทภารกิจ, พื้นที่ที่เผยแพร่ได้, ฝ่ายรับผิดชอบ, สรุป และรายละเอียด ใช้บรรทัดว่างคั่นย่อหน้า
3. ภาพปกไม่บังคับ หากใช้ต้องระบุ alt, เครดิต/ที่มา และยืนยันสิทธิ์เผยแพร่ รับ JPG/PNG/WebP ไม่เกิน 5 MB และกว้างอย่างน้อย 800 px
4. บันทึกเป็นร่าง เปิดพรีวิว `/admin/projects/[id]/preview` แล้วเผยแพร่จากหน้ารายการ เมื่อเผยแพร่จะปรากฏใน `/projects/[slug]`, หน้ารวม, หน้าแรก และผลค้นหา
5. ปิดเผยแพร่หรือเก็บถาวรได้ รายการและภาพปกจะไม่แสดงต่อสาธารณะ

## ข้อมูลและสิทธิ์

- `projects` เก็บเนื้อหา/สถานะ; `project_audit` เก็บผู้ทำ เวลา และค่าก่อน/หลังทุกการสร้าง แก้ หรือเปลี่ยนสถานะ
- public query ปกติคืนเฉพาะ `published`; โครงการจำลองที่ตั้ง `showcase_visible=true` มี query แยก และแสดงแทนเมื่อยังไม่มีโครงการจริงที่เผยแพร่ query และ Server Actions หลังบ้านตรวจ session + role `admin`; route ภาพร่างทั่วไปตอบ 404 ต่อผู้ไม่ล็อกอิน
- ภาพเก็บใน private Supabase Storage ไม่อยู่ใน `public/`; แปลงเป็น WebP และตัด metadata ก่อนเก็บ
- รายชื่อฝ่ายดึงจากข้อมูลโครงสร้างใน `src/content/static/site.ts` และตรวจซ้ำที่ server
- โครงการตัวอย่าง 6 รายการอยู่ใน Supabase เป็น `draft` + `is_mockup=true` พร้อม `showcase_visible=true` ตามคำขอให้แสดงบนหน้าแรกและหน้ารวม ป้ายกำกับบอกชัดว่าไม่ใช่ภารกิจจริงหรือช่องทางรับเงิน และฐานข้อมูลห้ามเปลี่ยนตัวอย่างเป็น `published`; รัน `node scripts/seed-project-mockups.mjs --apply` เพื่อเติมซ้ำโดยไม่สร้าง slug ซ้ำ
- การแก้โครงการที่เผยแพร่มีผลทันทีพร้อม audit; revision แยกสำหรับรออนุมัติยังไม่พร้อม

## ข้อมูลที่ยังไม่เก็บเป็น field เฉพาะ

เป้าหมาย ระยะเวลา สถานะภารกิจ ตัวเลขผลลัพธ์ หลักฐาน และความสัมพันธ์กับรายงาน/ข่าว ต้องออกแบบพร้อมแหล่งข้อมูลและ workflow อนุมัติ ห้ามเติมค่าตัวอย่างให้ดูเหมือนโครงการจริง การเลือกโครงการขึ้นหน้าแรกทำได้ที่ `/admin/homepage/features`

## สำรองและทดสอบ

`npm run backup:local` ใช้กับข้อมูล SQLite เดิมเท่านั้น ข้อมูลปัจจุบันใน Supabase ต้องมีแผนสำรองและทดสอบ restore แยกต่างหาก

ทดสอบกับฐานข้อมูลชั่วคราว: บันทึกร่างผ่าน UI แล้ว public ตอบ 404; เผยแพร่แล้วหน้ารวม/รายละเอียด/หน้าแรก/ค้นหาแสดงรายการ; ปิดเผยแพร่แล้วกลับเป็น 404
