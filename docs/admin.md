# ระบบหลังบ้าน CHNS

สถานะ: เปิดระบบ login ด้วย Supabase Auth และโมดูลสไลด์หน้าแรก ข่าว/บทความ โครงการ รายงาน PDF โลโก้ภาคี และการเลือกเนื้อหาเด่นผ่าน Supabase; โมดูล CMS อื่นยังเป็นแผน

## หน้าที่ของ admin

หลังบ้านใช้จัดการเนื้อหาที่เปลี่ยนบ่อยและต้องมีการอนุมัติ ได้แก่ ข่าว/บทความ, โครงการและผลลัพธ์, รายงาน, ศูนย์ประสานงาน, องค์กรสมาชิก/โลโก้, สื่อ, ส่วนที่เลือกขึ้นหน้าแรก และ emergency banner. ข้อมูลทางการที่เปลี่ยนไม่บ่อยเก็บในโค้ดได้ตาม [architecture.md](architecture.md) และแก้ผ่านการ review/deploy

## โมดูลเป้าหมาย

| โมดูล | งานหลัก | เงื่อนไขสำคัญ |
| --- | --- | --- |
| Dashboard | งานรอตรวจ, เนื้อหากำลังเผยแพร่, รายการล่าสุด | แสดงตามสิทธิ์ผู้ใช้ |
| Content | สร้าง/แก้/พรีวิวข่าวและหน้าโครงการ | revision, slug, taxonomy, metadata, schedule |
| Reports & media | อัปโหลด PDF/ภาพ, alt, caption, สิทธิ์เผยแพร่ | แยก public/private และจำกัดชนิด/ขนาดไฟล์ |
| Network | แก้ศูนย์และองค์กรสมาชิก | ข้อมูลบุคคลเผยแพร่เมื่อได้รับอนุญาต |
| Homepage & settings | เลือก featured, เปิด emergency banner | ตั้งวันเริ่ม/สิ้นสุดและมีผู้อนุมัติ |
| Users & audit | จัดการบัญชี/สิทธิ์, ดูประวัติการแก้ไข | เฉพาะผู้ดูแลระบบ |

ฟอร์มสมัครสมาชิกองค์กรเป็นอีกงานหนึ่ง เพราะมีข้อมูลส่วนบุคคลและเอกสารแนบ ผู้รับเรื่องต้องมีสิทธิ์เฉพาะ ไม่ควรให้ editor คอนเทนต์เห็นเอกสารทั้งหมด ระบบบริจาคจริงและการออกใบเสร็จต้องออกแบบแยกเมื่อทราบขั้นตอนการเงิน

## สิทธิ์เริ่มต้นที่เสนอ

| Role | สิทธิ์ |
| --- | --- |
| `editor` | สร้างและแก้ draft ในฝ่ายที่ได้รับมอบหมาย ส่งตรวจ |
| `reviewer` | ตรวจและขอแก้ไขเนื้อหาที่รับผิดชอบ |
| `publisher` | อนุมัติ/เผยแพร่/ถอนเผยแพร่ พร้อมเหตุผล |
| `admin` | จัดการผู้ใช้ สิทธิ์ การตั้งค่าและ audit |
| `caseworker` | รับเรื่องสมัครสมาชิกและดูเอกสารเฉพาะงาน ไม่ได้สิทธิ์เผยแพร่คอนเทนต์ |

สิทธิ์จริงต้องตรวจทั้ง **role + scope ของฝ่าย + สถานะเนื้อหา** ที่ server. หน้า admin, Server Actions, Route Handlers และการดาวน์โหลด private file ต้องตรวจแยกตามจุดเข้าถึง ไม่พึ่งเมนูที่ถูกซ่อนหรือ layout อย่างเดียว

## วงจรเผยแพร่

1. Editor สร้าง draft และระบุแหล่งข้อมูล/สิทธิ์สื่อ
2. Reviewer ตรวจเนื้อหาและความครบถ้วน ส่งกลับหรือรับรอง
3. Publisher เผยแพร่; ระบบบันทึก revision, ผู้ทำ, เวลา และ revalidate หน้าเว็บที่เกี่ยวข้อง
4. การแก้ไขหลังเผยแพร่เริ่ม revision ใหม่; การถอนเผยแพร่ต้องเก็บเหตุผลและมีผลต่อ sitemap/search

## เกณฑ์ความพร้อมก่อนใช้งานจริง

- Login/session ผ่าน auth library ที่ดูแลได้; จำกัดสิทธิ์และป้องกัน brute force ตามบริการที่เลือก
- Server-side validation, authorization ใน data access layer และทุก mutation, audit log
- Backup/restore ของฐานข้อมูลและไฟล์; แผนสิทธิ์การเข้าถึงของทีมงาน
- อัปโหลดไฟล์มีชนิด/ขนาดที่อนุญาตและการสแกน; เอกสารส่วนตัวไม่อยู่ใน `public/`
- Staging สำหรับทดสอบก่อน production; ทดสอบ editor ไม่สามารถ publish และผู้ไม่ login อ่าน draft ไม่ได้

โมดูลคอนเทนต์ใช้ Supabase Auth/PostgreSQL/Storage แล้ว ผู้ดูแลเปลี่ยนรหัสผ่านได้ที่ `/admin/account`; ขั้นตอนตั้งค่าอยู่ใน [supabase-setup.md](supabase-setup.md)

## แผนหน้าจอหลังบ้านสำหรับเฟส 2

| Route เป้าหมาย | หน้าจอ | ข้อมูล/การกระทำหลัก |
| --- | --- | --- |
| `/admin/login` | เข้าสู่ระบบ | session, การกู้บัญชีตามวิธีที่องค์กรเลือก |
| `/admin` | Dashboard | งานของฉัน, รอตรวจ, กำลังเผยแพร่, ความผิดพลาดสื่อ |
| `/admin/projects`, `/admin/projects/[id]` | รายการและตัวแก้โครงการ | สถานะ พื้นที่ ฝ่าย เป้าหมาย ผลลัพธ์ หลักฐาน โครงการที่เกี่ยวข้อง |
| `/admin/articles`, `/admin/articles/[id]` | ข่าว/บทความ/วิดีโอ | ประเภท หัวเรื่อง เนื้อหา วันที่ แหล่งข่าว ความสัมพันธ์และ SEO |
| `/admin/reports`, `/admin/reports/[id]` | รายงาน | ประเภท ปี เจ้าของข้อมูล ไฟล์เผยแพร่และสิทธิ์ |
| `/admin/departments` | ข้อมูลฝ่าย | คำอธิบายที่แก้บ่อย featured และความสัมพันธ์กับคอนเทนต์; ชื่อ/slug ที่เป็นโครงคงในโค้ด |
| `/admin/centers`, `/admin/members` | เครือข่าย | ศูนย์ พื้นที่ติดต่อ องค์กรสมาชิก โลโก้ สิทธิ์เผยแพร่ |
| `/admin/media` | คลังสื่อ | อัปโหลด alt caption credit consent สถานะตรวจสิทธิ์ |
| `/admin/homepage` | หน้าแรก | เลือกคอนเทนต์ featured และ emergency banner |
| `/admin/settings` | ข้อมูลกลาง | ช่องทางติดต่อที่อนุมัติ social และวิธีสนับสนุน |
| `/admin/users`, `/admin/audit` | ผู้ใช้และประวัติ | role, scope ฝ่าย, revision, การอนุมัติ/ถอนเผยแพร่ |

ในตารางนี้ `/admin/login`, `/admin`, `/admin/homepage/slides`, `/admin/homepage/features`, `/admin/articles`, `/admin/projects` และ `/admin/reports` มีหน้าจอจริงแล้ว (รวมหน้าเพิ่ม/แก้และพรีวิวสำหรับข่าว/โครงการ). โมดูลคอนเทนต์ยังจำกัดสิทธิ์ที่ `admin` และการแก้รายการเผยแพร่มีผลทันทีพร้อม audit; role หลายระดับและ revision ที่รออนุมัติยังต้องทำก่อนปิดเฟส 2. Route อื่นยังเป็นเป้าหมาย ระบบรับสมัครองค์กรและเอกสารส่วนบุคคลจะเป็นพื้นที่เฉพาะ `caseworker` แยกจากตัวแก้คอนเทนต์ ดูรายละเอียดใน [hero-carousel-admin.md](hero-carousel-admin.md), [article-admin.md](article-admin.md), [project-admin.md](project-admin.md), [report-admin.md](report-admin.md) และ [homepage-features.md](homepage-features.md)
