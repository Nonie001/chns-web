# แผนภาพจริงสำหรับเว็บไซต์ CHNS

ตรวจจากหน้าเว็บและระบบอัปโหลดวันที่ 6 ตุลาคม 2569 เอกสารนี้เป็นรายการเตรียมภาพและขนาดแนะนำสำหรับ **การออกแบบ/ครอป** ไม่ใช่เงื่อนไขขั้นต่ำของระบบทุกช่อง ภาพที่ใช้เป็นหลักฐานกิจกรรมต้องมีที่มาและสิทธิ์เผยแพร่ก่อนลงเว็บ

## ทิศทางใหม่: ภาพพื้นหลัง Hero ของหน้าใน

ภาพหน้าจอ `/centers` ที่ส่งมาเป็นแถบหัวพื้นสีอ่อน มีชื่อหน้าทางซ้ายและคำอธิบายทางขวา ผู้ใช้ต้องการให้หัวหน้าในและส่วนอื่น ๆ ใช้ภาพมากขึ้น **นี่เป็นแผนปรับดีไซน์**; ตอนนี้ `PageHero` ยังมีแบบข้อความล้วนกับแบบภาพข้างข้อความ ยังไม่มีแบบภาพเต็มพื้นที่พร้อมตัวอักษรทับภาพ ส่วนหน้าเกี่ยวกับเรา งานของเรา และร่วมสนับสนุนเขียนหัวหน้าแยกจาก `PageHero`

### วิธีจัดภาพหัวหน้าใน

- ทำภาพเต็มความกว้างสูงราว 360–520 px บน desktop และ 320–440 px บนมือถือ (กำหนดจริงหลังลองกับภาพ) เก็บ breadcrumb บนพื้นเรียบเหนือภาพ
- ชื่อหน้าและคำอธิบายเป็น **ตัวอักษร HTML** ทับภาพ ไม่ฝังลงในไฟล์ เพื่ออ่านได้ทุกจอและรองรับการเข้าถึง ใช้ overlay/gradient ที่พอให้ตัวอักษรชัด; ตรวจบนภาพจริงแต่ละใบ
- ขอภาพต้นฉบับแนวนอนอย่างน้อย 3000 × 2000 px แล้วส่งครอป **desktop 2400 × 1000 px (ประมาณ 2.4:1)** และ **mobile 1200 × 1500 px (4:5)** ต่อภาพหัวเรื่อง ภาพมือถือควรจัดองค์ประกอบใหม่จากต้นฉบับ ไม่ใช้การตัดกลางอัตโนมัติ
- ถ้าจะวางตัวอักษรซ้ายแบบในภาพตัวอย่าง ให้เว้นพื้นที่เรียบ/รายละเอียดน้อยทางซ้ายประมาณ 40–45% ของภาพ desktop และให้จุดสำคัญของภาพอยู่ทางขวา บนมือถือเว้นพื้นที่สำหรับตัวอักษรช่วงล่างหรือใช้พื้นทึบกึ่งโปร่งใสหลังข้อความ ห้ามวางใบหน้าหรือข้อความสำคัญตรงจุดครอป
- ภาพพื้นหลังเป็นบรรยากาศของหมวด ไม่ควรใช้ภาพเหตุการณ์หนึ่งเพื่อสื่อว่าเป็นทุกโครงการ/ทุกศูนย์ หากภาพมีเหตุการณ์จริง ให้มีคำบรรยายและเครดิตที่ผ่านการตรวจในบริเวณใกล้ภาพ

### รายการภาพ Hero ที่ควรหา

| กลุ่มหน้า | จำนวนภาพเริ่มต้น | เนื้อหาภาพที่เหมาะ | หมายเหตุ |
| --- | ---: | --- | --- |
| หน้าแรก `/` | 1–3 เรื่อง × 2 ครอป | ภารกิจเด่นที่มีสิทธิ์เผยแพร่ | ใช้ระบบสไลด์เดิม; ขนาด H1/H2 ด้านล่าง ไม่ใช่สัดส่วน Hero หน้าใน |
| `/about` และหน้าประวัติ/ทิศทาง/โครงสร้าง | 1 ภาพหลัก | ภาพองค์กรหรือการทำงานร่วมกันที่ยืนยันได้ | หน้าย่อยใช้ภาพในธีมเดียวกันก่อน ถ้ามีเรื่องเฉพาะจึงค่อยแยก |
| `/departments` และ 8 หน้าฝ่าย | 1 ภาพรวม; ภาพเฉพาะฝ่าย 8 ใบเป็นระยะถัดไป | การทำงานของฝ่ายหรือทีมที่ตรงกับชื่อฝ่าย | อย่าใช้ภาพเดียวซ้ำทั้ง 8 หน้าเมื่อมีภาพจริงเฉพาะฝ่าย |
| `/projects` | 1 ภาพรวม | ภารกิจภาคสนามที่ได้รับอนุมัติ | หน้ารายละเอียดใช้ภาพปกของโครงการนั้น ไม่ใช้ภาพหมวดแทน |
| `/news` | 1 ภาพรวม | งานบันทึก/สื่อสารภารกิจจริง | หน้าบทความใช้ภาพปกของบทความนั้น |
| `/centers` | 1 ภาพ | การประสานงานพื้นที่จริงหรือทีมศูนย์ | เป็นหน้าตัวอย่างที่ผู้ใช้แนบมา; ตอนนี้มีภาพประกอบในเนื้อหาอีกหนึ่งจุด |
| `/reports` | 1 ภาพ | การติดตามผล เอกสาร หรือการประชุมที่ยืนยันได้ | หน้ารายงานรายชิ้นควรเน้นข้อมูลและ PDF มากกว่าภาพตกแต่ง |
| `/media` | 1 ภาพ หรือใช้ภาพรวมที่มีอยู่ | ภาพเบื้องหลังการเก็บภาพภารกิจ | คลังภาพปัจจุบันดึงปกข่าว/โครงการ ไม่มีอัปโหลดสื่อแยก |
| `/participate` | 1 ภาพ | การร่วมงาน/การสนับสนุนที่สื่อสารอย่างถูกต้อง | หน้า donate/membership ใช้ภาพตามบริบทเมื่อมีข้อมูลและสิทธิ์ |

**ชุดเริ่มต้น:** Hero หน้าใน 7–8 ภาพหลัก (ภาพของ `/media` ใช้ร่วมกับหมวดอื่นได้) × 2 ครอป; ภาพหน้าแรกแยก 1–3 เรื่อง × 2 ครอป. ไม่ต้องรีบหาภาพ Hero แยกสำหรับ `/search`, `/contact`, `/privacy`, `/cookies` เพราะหน้าใช้งาน/นโยบายต้องอ่านชัดและไม่ควรเพิ่มภาพโดยไม่มีความหมาย หากอยากให้ทุก URL มีภาพ ให้ตัดสินหลังเห็นชุดภาพและแบบมือถือจริง

### ส่วนอื่นที่คุ้มเพิ่มภาพ

1. **หน้าแรก:** ภาพวิธีทำงาน 1 ใบ, ภาพปกโครงการ 2–6 ใบ, ภาพปกข่าว/เรื่องเล่า 3–6 ใบ จุดเหล่านี้มีกรอบภาพแล้ว
2. **เกี่ยวกับเรา:** ภาพองค์กรจริง 1–2 ใบในช่วงเล่าเรื่อง/ประวัติ และภาพเอกสารหรือช่วงเวลาสำคัญเมื่อมีข้อมูลยืนยัน ปัจจุบันยังเป็นข้อความล้วน
3. **งานของเรา:** ภาพสื่อบทบาทฝ่ายละ 1 ใบสำหรับ 8 ฝ่าย เฉพาะเมื่อได้ภาพตรงงานและมีสิทธิ์เผยแพร่ ปัจจุบันหน้าแรกและหน้ารวมฝ่ายเป็นรายการข้อความ ต้องพัฒนา layout และช่องข้อมูลเพิ่ม
4. **ศูนย์ประสานงาน:** ภาพ Hero 1 ใบและภาพการทำงานในเนื้อหา 1 ใบ โดยให้ภาพสองจุดเล่าคนละมุม ไม่ใช้ภาพเดียวซ้ำ
5. **ข่าว/โครงการ:** ภาพปก 1 ใบต่อเรื่องก่อน; แกลเลอรีภาพภาคสนามหรือภาพประกอบในบทความเป็นระยะถัดไป ต้องเพิ่มระบบหลายภาพ/คำบรรยายก่อน

ลำดับการออกแบบที่เหมาะคือทดลอง `/centers` เป็นแม่แบบ Hero ภาพพื้นหลังหนึ่งหน้า ตรวจครอป desktop/mobile และคอนทราสต์ข้อความ แล้วค่อยนำรูปแบบไปใช้กับกลุ่มหน้าที่เหลือ โดยยังไม่เผยแพร่ภาพที่ไม่ได้รับอนุมัติ

## ส่งภาพชุดแรกตามลำดับนี้

| ลำดับ | ภาพที่ต้องเตรียม | จำนวนเริ่มต้น | จุดที่ใช้ตอนนี้ |
| --- | --- | ---: | --- |
| 1 | ภาพ Hero ภารกิจ/องค์กรจริง | 1–3 เรื่อง × 2 ครอป (desktop, mobile) | สไลด์เต็มความกว้างหน้าแรก; จัดการใน `/admin/homepage/slides` |
| 2 | ภาพการทำงาน/ประสานงานจริง | 1 ภาพ | ช่วง “จากการประสานงานสู่การลงมือร่วมกัน” หน้าแรก แทน `home-packing.jpg` |
| 3 | ภาพปกโครงการจริง | 2–6 ภาพ (ตามโครงการที่อนุมัติ) | หน้าแรก หน้ารวม หน้ารายละเอียด และคลังภาพ; อัปโหลดใน `/admin/projects` |
| 4 | ภาพปกข่าว/เรื่องเล่าจริง | 3–6 ภาพ (ตามข่าวที่อนุมัติ) | หน้าแรก หน้ารวม หน้ารายละเอียด และคลังภาพ; อัปโหลดใน `/admin/articles` |
| 5 | ภาพประกอบหน้าหมวด | 3 เรื่อง | หัวหน้ารวมโครงการ ข่าว และรายงาน; ขณะนี้ใช้ไฟล์ใน `public/editorial/` |
| 6 | ภาพประกอบบริบทอื่น | 1–3 เรื่อง | ศูนย์ประสานงาน, หน้าฝ่ายงาน และหน้าร่วมสนับสนุน; ขณะนี้บางหน้าซ้ำภาพเดียวกัน |

หากมีภาพจริงเพียง 10–15 ภาพ ให้เริ่มที่ลำดับ 1–4 ก่อน ภาพปกหนึ่งภาพต่อหนึ่งเนื้อหานับเป็นไฟล์คนละเรื่อง ไม่จำเป็นต้องถ่ายภาพใหม่เพื่อการ์ดและหน้ารายละเอียดของเรื่องเดียวกัน

## ขนาดไฟล์ที่ขอจากทีมภาพ

ขนาดด้านล่างเป็น **ขนาดแนะนำของไฟล์ที่ส่งเข้าเว็บหลังครอป** เก็บต้นฉบับความละเอียดเต็มแยกไว้เสมอ พิกเซลระบุเป็นกว้าง × สูง

| รหัส | ตำแหน่ง / พฤติกรรมจริง | สัดส่วนที่เตรียม | ขนาดแนะนำ | ข้อควรระวัง |
| --- | --- | --- | --- | --- |
| H1 | Hero desktop เต็มหน้ากว้าง; ภาพหลัก `contain` และมีพื้นหลังภาพเบลอ | 16:9 | **2400 × 1350 px** | หากมีข้อความฝังในภาพ ต้องอ่านได้เมื่อย่อและเว้นขอบปลอดภัยประมาณ 10% |
| H2 | Hero mobile ใช้รูปแยกเมื่อจอ ≤700 px | 4:5 | **1200 × 1500 px** | จัดองค์ประกอบใหม่สำหรับจอแคบ อย่าย่อ H1 แล้วหวังให้ข้อความอ่านได้ |
| H3 | ภาพนิ่งสำรองหน้าแรกเมื่อไม่มีสไลด์เผยแพร่; `cover` จึงถูกครอปตามจอ | 16:9 | **2400 × 1350 px** | จุดนี้เป็นไฟล์ static แยกจาก CMS; `home-relief.jpg` ปัจจุบันเป็นภาพจำลอง |
| S1 | ภาพส่วน “จากการประสานงาน…” หน้าแรก; กรอบค่อนข้างสูงและใช้ `cover` | 4:5 | **1200 × 1500 px** | เผื่อพื้นที่รอบบุคคล/กิจกรรม เพราะกรอบเปลี่ยนตามจอ |
| C1 | ภาพปกข่าวและโครงการ: การ์ดกับหน้ารายละเอียด 16:10, คลังภาพ 4:3 | 4:3 หรือภาพกว้างที่ครอป 4:3 ได้ | **1800 × 1350 px** | วางตัวแบบสำคัญกลางภาพและเผื่อขอบ; ตรวจทั้งครอป 16:10 กับ 4:3 ก่อนส่ง |
| P1 | ภาพหัวหน้ารวมโครงการ/ข่าว/รายงาน; `cover` ในคอลัมน์ข้างข้อความ | 3:2 | **1600 × 1067 px** | บนมือถือกรอบเตี้ยลงและครอปมากขึ้น; เก็บจุดสำคัญกลางภาพ |
| P2 | ภาพประกอบศูนย์/ฝ่าย/ร่วมสนับสนุนในเนื้อหา | 3:2 | **1600 × 1067 px** | ตอนนี้ใช้ภาพ `coordination.webp` หรือ `participation.webp` ซ้ำหลายหน้า |
| L1 | โลโก้ภาคีในตาราง `contain` ไม่ครอป | ตามรูปทรงโลโก้; พื้นโปร่งใสถ้ามี | วางใน canvas ไม่เกิน **420 × 320 px** | อย่ายืดให้เต็มกรอบ; ระบบจะย่อให้อยู่ใน 420 × 320 |
| B1 | ตราสัญลักษณ์ CHNS ใน header/footer | 1:1 | **อย่างน้อย 256 × 256 px** | มีไฟล์ใช้งานแล้ว ไม่ต้องส่งใหม่ถ้าไม่เปลี่ยนตรา |

**กฎอัปโหลดที่ระบบใช้จริง:** Hero desktop ต้องกว้างอย่างน้อย 1200 px และอัตราส่วน ≥1.4:1; Hero mobile กว้างอย่างน้อย 600 px และอัตราส่วน ≤1.4:1. ภาพข่าว/โครงการกว้างอย่างน้อย 800 px; โลโก้ภาคีอย่างน้อย 200 × 100 px. ทุกประเภทรับ JPG/PNG/WebP ไม่เกิน 5 MB ต่อไฟล์ ระบบแปลงเป็น WebP และย่อ Hero desktop ไม่เกิน 2400 px, mobile ไม่เกิน 1200 px, ข่าว/โครงการไม่เกิน 1800 px, โลโก้ไม่เกิน 420 × 320 px. ขนาดแนะนำด้านบนจึงไม่ควรเข้าใจว่าเป็นขั้นต่ำของฟอร์ม

ภาพกิจกรรมควรส่ง JPG/WebP คุณภาพเหมาะสมโดยไม่บีบจนรายละเอียดใบหน้าหรือข้อความเสีย; โลโก้ควรส่ง PNG/WebP ที่มี transparency หากต้นฉบับมีพื้นโปร่งใส ภาพฝังข้อความบน Hero ต้องทำทั้ง H1 และ H2 และตรวจสะกด/ความอ่านง่ายบนโทรศัพท์จริง

## ผังจุดภาพปัจจุบันและวิธีแทน

| หน้า | จุดภาพปัจจุบัน | วิธีใส่ภาพจริง |
| --- | --- | --- |
| `/` | Hero: สไลด์ published หรือภาพนิ่ง `public/editorial/home-relief.jpg` | เพิ่มสไลด์จริงในหลังบ้าน; ภาพนิ่งสำรองยังเป็นไฟล์ static ที่ต้องเปลี่ยนเมื่อพร้อม |
| `/` | ช่วงวิธีทำงาน: `public/editorial/home-packing.jpg` | เปลี่ยนไฟล์ static หลังตรวจภาพ/คำกำกับ |
| `/`, `/projects`, `/projects/[slug]`, `/media` | ปกโครงการจากข้อมูลโครงการ | อัปโหลดภาพใน `/admin/projects`; เผยแพร่เฉพาะรายการที่ผ่านการตรวจ |

| `/projects`, `/news`, `/reports` | ภาพหัวหมวด `work-areas.webp`, `participation.webp`, `transparency.webp` | จุดนี้ยังใช้ไฟล์ static; ยังไม่มีฟอร์มอัปโหลดภาพหัวหมวด |
| `/centers`, `/departments/[slug]`, `/participate/donate` | ภาพประกอบ `coordination.webp`/`participation.webp` | จุดนี้ยังใช้ไฟล์ static และบางหน้าซ้ำภาพ; เลือกภาพให้ตรงเรื่องก่อนแทน |
| `/`, `/#network` | โลโก้ภาคี published | เพิ่ม/แก้ใน `/admin/partners`; โลโก้ชุดเดิมเผยแพร่แล้ว |

หน้า `/media` **ยังไม่ใช่คลังอัปโหลดภาพอิสระ**: รวมภาพปกของข่าวและโครงการที่เผยแพร่แล้วเท่านั้น และส่วนวิดีโอยังเป็นข้อความรอเนื้อหา หน้าแสดงรายงานใช้ PDF ไม่ได้มีช่องภาพปกรายงานใน CMS ปัจจุบัน หน้าแรกส่วนฝ่ายงานเป็นรายการข้อความ 8 ฝ่าย ยังไม่มีช่องภาพรายฝ่าย อย่าส่งภาพ 8 ใบโดยคาดว่าจะอัปโหลดได้ทันที ต้องออกแบบและเพิ่มช่องข้อมูลก่อน

## ข้อมูลที่ขอพร้อมรูปแต่ละชุด

ใช้หนึ่งแถวต่อภาพหรือหนึ่งแถวต่อเรื่องที่มี desktop/mobile คู่กัน ทีมสามารถคัดลอกตารางนี้ไปกรอก:

| รหัสจุด | ชื่อไฟล์ | เรื่อง/หน้าที่ใช้ | วันที่และพื้นที่จริง | ผู้ถ่าย/แหล่งภาพ | ผู้มีสิทธิ์และขอบเขตอนุญาต | บุคคลในภาพอนุญาตเผยแพร่หรือไม่ | คำบรรยาย/alt ที่ตรวจแล้ว | สถานะอนุมัติ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| H1 + H2 |  |  |  |  |  |  |  |  |
| C1 |  |  |  |  |  |  |  |  |

ถ้าภาพมีผู้รับความช่วยเหลือ เด็ก เอกสารส่วนบุคคล หรือสถานที่อ่อนไหว ให้ตรวจการยินยอมและข้อมูลที่มองเห็นในภาพก่อนส่งเผยแพร่ ภาพตัวอย่างที่อยู่ในเว็บขณะนี้ไม่ควรถูกระบุว่าเป็นภาพปฏิบัติงานจริงของ CHNS

## งานรองรับภาพที่ยังต้องพัฒนาเมื่อได้ชุดภาพจริง

1. เปลี่ยนภาพ static ใน `public/editorial/` และคำกำกับภาพให้ตรงกับภาพจริงที่ตรวจแล้ว; เผยแพร่เฉพาะไฟล์ที่อนุญาตให้เข้าถึงสาธารณะ
2. ถ้าต้องการให้ทีมงานเปลี่ยนภาพหัวหมวด/ภาพวิธีทำงานเองโดยไม่ deploy ให้เพิ่มช่องในหลังบ้านพร้อมตรวจสถานะและสิทธิ์ไฟล์ก่อนเสิร์ฟ
3. ถ้าต้องการภาพรายฝ่าย แกลเลอรีหลายภาพต่อข่าว/โครงการ วิดีโอ หรือปกรายงาน ให้เพิ่มโมเดลข้อมูลและ UI แยก; ยังไม่มีช่องเหล่านี้ในเว็บปัจจุบัน
4. ตรวจครอป desktop/mobile, alt, เครดิต และความเร็วโหลดหลังนำภาพจริงเข้าระบบ; ภาพข่าว/โครงการและโลโก้ที่เสิร์ฟจาก `/api/` ปัจจุบันใช้ `unoptimized` จึงส่งไฟล์ WebP ที่จัดเก็บไว้โดยตรง
