# ประเด็นรอตัดสินใจก่อนพัฒนาระบบจริง

| ประเด็น | ข้อเสนอปัจจุบัน | ต้องได้ข้อมูลอะไรเพิ่ม |
| --- | --- | --- |
| URL เว็บเดิม | ตรวจ inventory ก่อนล็อก route และ redirect | domain, sitemap, หน้าเดิม, analytics |
| การเผยแพร่ภาษาอังกฤษ | พักการพัฒนาไว้ตามคำขอผู้ใช้; เปิดเว็บภาษาไทยก่อน | รอคำสั่งให้เริ่มและผู้รับผิดชอบคำแปลที่อนุมัติ |
| ฐานข้อมูล | ใช้ Supabase PostgreSQL/RLS แล้ว; SQLite เหลือเป็นข้อมูลเดิมสำหรับ backup/import | staging, แผน backup/restore |
| Auth/บัญชี admin | ใช้ Supabase Auth พร้อม RLS และบัญชีผู้ดูแลคนแรกแล้ว | วิธีเชิญผู้ใช้เพิ่ม, MFA/SSO และ role ของ editor/reviewer |
| ORM และ migration | เลือกหลังล็อก database/host | รูปแบบ deploy และผู้ดูแลฐานข้อมูล |
| CMS | สร้าง admin ใน Next.js codebase นี้ตามขอบเขตใน `admin.md` | workflow ที่องค์กรยืนยันและจำนวน editor |
| ไฟล์/ภาพ | ใช้ private Supabase Storage พร้อม route ตรวจสถานะก่อนคืนไฟล์แล้ว | policy สิทธิ์ภาพ/เก็บรักษา/การสแกนไฟล์ |
| การรับบริจาค | พักระบบบริจาคไว้ตามคำขอผู้ใช้; ไม่เปิดรับเงินจริง | รอคำสั่งให้เริ่มและขั้นตอนการเงินที่องค์กรอนุมัติ |
| สมัครสมาชิกองค์กร | พักฟอร์มและ workflow สมัครสมาชิกไว้ตามคำขอผู้ใช้ | รอคำสั่งให้เริ่มและขั้นตอนรับเรื่อง/เก็บเอกสาร |
| เรื่องติดต่อจากเว็บไซต์ | รับเข้า Supabase inbox หลังบ้านและติดป้ายฝ่ายที่ผู้ส่งเลือก; เฉพาะ admin อ่านและเปลี่ยนสถานะได้ | อีเมลปลายทางรายฝ่าย/การแจ้งเตือน, ผู้รับผิดชอบแต่ละฝ่าย และระยะเวลาเก็บข้อมูล |
| ข้อมูล static | ชื่อองค์กร ประวัติ/ฝ่าย/คำ UI ที่อนุมัติ เก็บในโค้ด | เจ้าของข้อมูล, รอบการเปลี่ยน, ผู้อนุมัติ |
| โลโก้และภาพภารกิจ | ใช้โลโก้ที่ผู้ใช้ส่งมา ย่อเป็น WebP สำหรับเว็บและ PNG สำหรับไอคอน; ภาพ AI จำลอง 3 ภาพอยู่ในร่างสำหรับพรีวิว | ภาพภารกิจจริงและสิทธิ์เผยแพร่ภาพ |
| ข้อความหน้าเว็บเฟส 1 | เป็นสำเนาสำหรับตรวจทาน; เว็บไซต์ `noindex` | ผู้อนุมัติข้อความ และข้อความสุดท้ายขององค์กร |

รายการที่ยังไม่ยืนยันจะไม่ถูกแปลงเป็น dependency หรือ route ของโมดูลอื่น การเลือก Supabase เป็นทิศทางเป้าหมายแล้ว รายละเอียดและสิ่งที่ยังต้องทำก่อนสลับระบบอยู่ใน [supabase-setup.md](supabase-setup.md)
