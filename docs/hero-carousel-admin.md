# สไลด์ภาพหน้าแรกและหลังบ้าน

สถานะ: โมดูล Hero ใช้ Supabase แล้ว; ข่าว/บทความ โครงการ และรายงาน PDF มีโมดูลแยก ส่วนสมาชิกยังไม่ใช่ CMS จริง

## การทำงาน

- หน้าแรกแสดงเฉพาะภาพสไลด์ ไม่มีข้อความ ปุ่ม CTA หรือป้ายซ้อนบนภาพ มีปุ่มลูกศรก่อนหน้า/ถัดไป จุดเลือกสไลด์ และปัดบนมือถือ
- สไลด์เลื่อนอัตโนมัติทุก 6 วินาที วนจากภาพสุดท้ายกลับภาพแรกและเล่นต่อแม้ผู้ใช้กดเลือกภาพเอง; ปิดการเลื่อนอัตโนมัติเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหว
- หลังบ้าน `/admin/homepage/slides` เพิ่ม แก้ไข จัดลำดับ เผยแพร่ ปิดเผยแพร่ เก็บถาวร และคืนค่าร่างได้
- สไลด์ใหม่เริ่มเป็น `draft`; หน้าแรกอ่านเฉพาะ `published` และใช้ลำดับ `position`
- หลังบ้านเก็บชื่อสไลด์สำหรับจัดการ, ภาพหน้าจอกว้าง, ภาพมือถือ (ไม่บังคับ) และ alt text; ข้อความที่ต้องการให้เห็นต้องออกแบบลงในไฟล์ภาพ การแก้ไขสไลด์ที่เผยแพร่แล้วมีผลทันทีและบันทึก audit log
- สไลด์ภาพจำลอง 3 ภาพอยู่ใน Supabase เป็น draft สำหรับพรีวิวหลังบ้านเท่านั้น หน้าแรกจะแสดง Hero เมื่อมีสไลด์จริงที่เผยแพร่

## เริ่มใช้งานในเครื่อง

1. สร้าง `.env.local` จาก `.env.example` โดยใช้ Supabase Project URL และ publishable key
2. รัน `npm install` และ `npm run dev` แล้วเปิด `/admin/login`
3. ใช้บัญชีผู้ดูแลที่บันทึกใน Supabase Auth และ `chns_admin_users`; ขั้นตอนอยู่ใน [supabase-setup.md](supabase-setup.md)

## ภาพและที่เก็บ

- ภาพหน้าจอกว้างรองรับ JPG/PNG/WebP ไม่เกิน 5 MB, กว้างอย่างน้อย 1200 px และอัตราส่วนอย่างน้อย 1.4:1
- ภาพมือถือไม่บังคับ กว้างอย่างน้อย 600 px อัตราส่วนไม่เกิน 1.4:1 และไม่เกิน 5 MB; ถ้าไม่มีจะใช้ภาพหน้าจอกว้าง ระบบแสดงภาพทั้งหมดด้วย `contain` และพื้นหลังเบลอ เพื่อไม่ตัดข้อความที่ฝังในภาพ
- เซิร์ฟเวอร์ตรวจชนิดจากเนื้อไฟล์ แปลงเป็น WebP และตัด metadata ก่อนเก็บใน private Supabase Storage
- ฐานข้อมูลและไฟล์อยู่ใน Supabase ต้องมีแผนสำรองและทดสอบกู้คืนบนโฮสต์จริง
- ภาพร่างและภาพที่ปิดเผยแพร่เสิร์ฟเฉพาะ session ผู้ดูแล; ภาพเผยแพร่เข้าถึงได้จาก `/api/hero-images/[key]`
- ผู้ดูแลต้องตรวจสิทธิ์ภาพและข้อความเองก่อนเผยแพร่ ระบบยังไม่มีขั้นตอนรับรองสิทธิ์สื่อแบบหลายคน

## ขอบเขตความปลอดภัยและการนำขึ้นโฮสต์

ใช้ Supabase Auth กับอีเมล/รหัสผ่าน และ RLS. ทั้ง layout หลังบ้าน, data access และทุก Server Action ตรวจ session/role. รูปภาพตรวจสถานะอีกครั้งใน Route Handler ตามแนวทาง [Next.js Data Security](https://nextjs.org/docs/app/guides/data-security). มีตาราง `hero_slide_audit` เก็บผู้กระทำ เวลา และค่าก่อน/หลัง

ยังไม่มี workflow `editor → reviewer → publisher`, MFA, การสแกนไฟล์จากบริการภายนอก หรือ CMS เครือข่ายและคลังสื่อร่วม

## การตรวจรอบนี้

- บัญชีไม่ล็อกอินเข้าหลังบ้านแล้วถูกส่งไป `/admin/login`; บัญชี role `user` เข้าหลังบ้านไม่ได้
- ทดสอบเพิ่มภาพเป็นร่าง: หน้าแรกไม่แสดงและ media endpoint ตอบ 404 สำหรับผู้ไม่ล็อกอิน
- ทดสอบเผยแพร่: หน้าแรกเปลี่ยนเป็นสไลด์ที่เพิ่มและ media endpoint ตอบ 200; ปิดเผยแพร่แล้วกลับเป็นภาพตัวอย่างและ endpoint ตอบ 404
- `npm run supabase:verify`, `npm run lint`, `npm run build` ผ่านหลังการย้าย
